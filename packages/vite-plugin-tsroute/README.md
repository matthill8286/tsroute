# @atomic-ui/vite-plugin-tsroute

Keeps the TypeScript generated by [tsroute](https://github.com/matthill8286/tsroute) in step with your Rust API while `vite dev` runs. Save a `.rs` file and the client, hooks and Zod schemas regenerate. Vite hot-reloads them, and TypeScript flags every call site that no longer matches.

```sh
npm i -D @atomic-ui/vite-plugin-tsroute
```

```ts
// vite.config.ts
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import tsroute from "@atomic-ui/vite-plugin-tsroute";

export default defineConfig({
  plugins: [react(), tsroute({ crate: "../api" })],
});
```

On the Rust side, name your export test `tsroute_export` (or pass your own `command`):

```rust
#[test]
fn tsroute_export() {
    tsroute::Exporter::new()
        .client("../web/src/api/client.ts")
        .react_query("../web/src/api/hooks.ts")
        .zod("../web/src/api/schemas.ts")
        .sync()
        .unwrap();
}
```

If the Rust code doesn't compile, the error shows in Vite's error overlay. `vite build` regenerates first and fails the build if that fails.

| Option | Default | |
|---|---|---|
| `crate` | `".."` | Rust crate directory, relative to the Vite root |
| `watch` | `["src"]` | Paths to watch, relative to `crate` (`Cargo.toml` is always watched) |
| `command` | `"cargo test --quiet tsroute_export"` | What regenerates the TypeScript |
| `debounce` | `150` | ms to wait after the last change |
| `runOnStart` | `true` | Regenerate when the dev server starts |
| `runOnBuild` | `true` | Regenerate (and fail on error) during `vite build` |
